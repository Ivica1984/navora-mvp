## 2. A fact the hypothesis may not have used (IMPLEMENTED as reading)

Before a home-care search starts, the case **already carries the residence canton** (`residence_canton`, required by readiness). For the two pilot regions (FE-019) the canton codes `BS` and `BL` correspond one to one to Basel-Stadt and Basel-Landschaft. A derivation «region from residence canton» would therefore need **no new data field and no postcode table**, only a mapping of two codes per organisation. This is an observation, not a proposal of a rule: whether a team region is always a whole canton (FE-019 names regions, not cantons) is OPEN for `po`; for a nursing-home ward the region is the home's (PO row), not the client's.

Limit (IMPLEMENTED as reading): the partner request (`partner_requests.region`) is written **before** the case and its residence facts exist, so on today's flow the region of a referral cannot be derived from `residence_canton` at the time the request is recorded; it could only be checked or corrected at «Fall eröffnen» / readiness. Where that check would sit is OPEN for `po` and `uxa` (PO row: shown, one-tap correction, never silent).

## 3. Which official source would keep a postcode-to-canton table current? UNKNOWN (not verified in this run)

Candidates known to `eng` from general knowledge, **not fetched or checked here**; the owner or `lca` must confirm source, licence and update rhythm before any table is built:

- swisstopo «Amtliches Ortschaftenverzeichnis» (official directory of localities with postcode, municipality and canton), published as open data; update rhythm and licence: UNKNOWN until checked.
- BFS «Amtliches Gemeindeverzeichnis der Schweiz» (municipality numbers and their canton, with mutation history): gives municipality → canton, not postcode → canton.
- Swiss Post postcode data: terms and licence UNKNOWN.

Known structural point (to be verified by `lca` with the source, FE-019 boundary question in the PO row): a postcode is a postal delivery area, not a municipality; one postcode can cover several municipalities, so a postcode-to-canton mapping is not always unique. A municipality-to-canton mapping (BFS) is unique at a given date. **No postcode or municipality list is added to the repository by this probe**, and none would be added without a named source, its licence and a dated version (no invented data).

## 4. Engineering view, if the PO later opens a build (PLANNED, not started)

- Smallest option: derive or check the region from the existing `residence_canton` (section 2); no new personal data field (data minimisation question stays with `lca`).
- Postcode option: a versioned reference table (source, version date, licence in the migration header), read-only for `authenticated`, loaded by migration from a named file; ambiguous postcodes return «nicht eindeutig» and require a pick, never a silent default; pgTAP for the ambiguous case and for an unknown postcode; audit row when a derived region is overridden.
- Either option touches the referral and matching path, so it would be its own sub-block after B1.1-2 with `cra` and `lca` gates; it does not change #1164, B1.1-1b or B1.1-1c.
