## Result (IMPLEMENTED as reading, not as a test)

**Seed:** 41 rows carry a region; **40 of them are not on the list** (Basel-Stadt, Basel-Landschaft).

- **4 distinct legacy texts, 10 legacy rows in `region_legacy_values`** (one per organisation and value, over 8 organisations) after `supabase db reset`.
- **None maps automatically:** the normalised forms (`bernwest`, `bernost`, `zürichpilot`, `baselpilot`) equal neither `baselstadt` nor `basellandschaft` (`private.region_norm`, migration 0127 section 2).
- So in the seed **every organisation except …0019 has all its teams and cases on legacy values**. A new referral can carry only a list region (#1164), so in those organisations a new search finds no team of its region until «Zuordnen» has run (the CGR clinical-governance note PO 04:39 already describes this effect).

**e2e (Playwright, #1164 head):** creates **no** legacy value. Every region the UI writes is chosen from the list (`admin.spec.ts`, `intake.spec.ts`, `journey.spec.ts`, `durchgang-ambulant.spec.ts`, `safe-d11.spec.ts`, `b1-1-1-regions.spec.ts`). `b1-1-1-regions.spec.ts` uses the seed's «Basel Pilot» value of org A and maps it to Basel-Landschaft; that is the only e2e mapping.

**pgTAP:** fixtures write further legacy values inside their own transaction (most often «Bern West», 64 literals; also «Bern Nord», «Zürich Süd» and others). They are rolled back per file and are not left in the database.

## What this means for the challenge (analysis; the decision is the PO's)

1. The hypothesis holds for the data: Phase A needs «Zuordnen» **only because our own seed writes legacy values**. If the seed wrote only list regions, Phase A would have no value to map apart from test fixtures.
2. The seed's Bern and Zürich names predate FE-019 (pilot regions Basel-Stadt, Basel-Landschaft) and the seed header still says the names «match the two regions hard-coded in the Teams page (TD-13)», which TD-13 removed. That is a stale comment and a deviation from FE-019 in synthetic data, not a safety defect. Recorded, not changed (CLAUDE.md: document, do not change automatically).
3. Moving the seed to list regions is **not free**: the attention-rule coverage (T5), the team/case matching pairs in e2e, the isolation checks between organisations (org B uses «Bern West» on purpose, seed line 126) and at least the #1164 e2e on «Basel Pilot» depend on the current values. It would be its own PR with its own tests, after #1164 and the CGR-201 fix.
4. Keeping one or two legacy values in the seed on purpose is useful anyway: they are the only Phase A fixture that exercises «Region nicht zugeordnet», «Zuordnen» and (after the CGR-201 fix) the stray-row safety net end to end. Phase B migration will need exactly this path.

## Proposal (PLANNED, needs a PO decision)

- Option A (smallest change): keep the seed as it is; «Zuordnen» stays a Phase A feature with real seed data to work on.
- Option B (recommended by `eng`): after the CGR-201 fix PR, one seed PR that moves the bulk of the seed to Basel-Stadt / Basel-Landschaft (FE-019) and keeps exactly two deliberate legacy values (one mapped by e2e, one left unmapped for the listing and the guard tests), fixes the stale TD-13 comment, and adapts the dependent tests in the same PR. No test is removed or weakened; every changed expectation is named in the PR.
- Option C: move everything to list regions and keep legacy values only in pgTAP fixtures. Not recommended: e2e would no longer cover «Region nicht zugeordnet».

The CGR-201 fix stays first in any option (PO 06:39 decision 1): the guard must hold whatever the data hold.
