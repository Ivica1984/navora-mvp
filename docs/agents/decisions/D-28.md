# D-28 — When an overdue, stuck, uncovered or unfinished visit raises an exception

## Decision summary
Thresholds, priorities and recipients of the visit safety signals: a planned visit not started (`visit_overdue`), a visit left `on_the_way`, `started` or `paused` (`visit_stuck`), a planned visit with nobody responsible (`visit_uncovered`), a report or report correction not final (`report_not_final`, `report_correction_open`), and whether a hand close may silence any of them. **No recommendation yet.** Values of a safety threshold are a clinical rule: the PO proposes none. Expected route: `clinical` (the named Clinical Owner, G-1), with the PO deciding only the non-clinical parts (who sees a signal in the app, how it is shown).

## Context and problem statement
**Blocks:** the PROVISIONAL label of CSR1's thresholds. **Findings:** CGR-23, CGR-35 (open, advisory); CGR-04, CGR-22, CGR-24 (closed with provisional thresholds).

**What NAVORA does today (IMPLEMENTED, all PROVISIONAL in the Clinical Rule Register):**
- CR-038 `visit_overdue`: P2 at the planned start, P1 one hour later; untimed visits count from 00:00 (0038).
- CR-039 `visit_stuck`: P2 after 1 h without a status change (started: 1 h after the planned end), P1 after 3 h (0038).
- CR-040 / CR-049 `visit_uncovered`: stays after the planned start while nobody is responsible; P2, 24 h window; not closable by hand (0038, 0044).
- CR-041: a safety exception (P1 or escalating to P1) cannot be closed by hand (0039).
- CR-053 `report_correction_open`: P3 after the organisation's `report_not_final` threshold; not closable by hand (0047).
- `public.team_visit_alerts()` shows them to every member of the visit's team; OPS1 shows them to Operations (0038:140-175).
- Since migration 0055 (ADR-068, 2026-10-24) every date bound uses the Europe/Zurich day.

**Safe default in force:** the strict provisional thresholds above; no hand close for a safety signal.

A change of a default value is a one-row migration (options A and B: no build beyond that row and the register label).
- **Organisation overrides exist already** (`public.exception_rule_overrides`, 0035 §6, :500-523): set by `public.set_exception_rule` (organisation admin only, `private.is_org_admin`; idempotent; audited by trigger `write_audit_event` on priority, amount, escalation). The range check `private.exception_rule_range` (0035:527-535, 575-582) allows: for a P1-default rule never a later threshold; for the others **0 up to twice the default** (max 720) in the same unit; escalation to P1 never later than the default; priority never lower. On synthetic data no override is expected to exist; `eng` to confirm.
- **Clock semantics in code (CGR-23 confirmed):** `visit_stuck` is measured from the last `visit_events` row (0038:118-131); every pause or resume writes one, so the clock restarts. Untimed visits use 00:00 Zurich (0038:91-112).
- **Cost of option C (team choice inside a clinical band):** one migration: band columns on `exception_rules` (earliest P2, latest P1, set only from the Clinical Owner's approved values; while null, no team value is accepted); a team-level override table keyed by `team_id`; the resolver uses the team that owns the visit (also for a covered visit, CGR-21); a permission check (who may change it: `clinical`, `cra` condition 4); audit trigger as in 0035; ADM1 settings section. pgTAP: out-of-band refused; no switch-off; CR-041 hand-close refusal untouched; covered visit uses the owner team's value. Comparable in size to 0035 §6. Reversible (dropping team rows falls back to organisation and default). Not built before a band exists.
- **Evidence AN2 can supply from events already stored:** planned start → first `on_the_way`/`started` event (`visit_events`); pauses and resumes per visit (`visit_events`); how exceptions end (`exception_events` kinds `take`, `close`, `auto_close`, with actor). SIG1-6 adds share taken and minutes to taken. Which AN2 measure carries which: `eng` to confirm.

## Clinical impact
*cra 2026-10-24 02:26 (copied from `reports/CLINICAL_GOVERNANCE.md` by po). Confirmed `cra` input, not a PO draft; copied verbatim.*

- **Hazards per signal** (H-01, H-07, H-15, H-16, H-17):
  - `visit_overdue` (CR-038): a missed visit noticed late, causing missed medication, nutrition, hygiene or wound care, or an unnoticed fall. Untimed visits count from 00:00, so they turn P2 at midnight: a likely source of alert fatigue unless untimed visits get a window.
  - `visit_stuck` (CR-039): a nurse or client in difficulty during a visit. The clock restarts with every pause or resume (CGR-23, PS-19), so a visit paused and resumed repeatedly never escalates.
  - `visit_uncovered` (CR-040/049): nobody goes. It stays P2 with a 24 h window and is not closable by hand.
  - `report_not_final` / `report_correction_open` (CR-053): the next carer works from an incomplete record.
  - `visit_interrupted` (D-31) and the absence flag (CGR-32/CGR-35): missed care that needs a follow-up decision.
- **Evidence for the provisional values.** None. They are strict engineering defaults (CSR1), not clinically derived. NAVORA has no pilot data. AN2 can supply: time from planned start to actual start, how exceptions end, and repeat pauses per visit. I know of no Swiss standard that fixes these values: UNKNOWN; the Clinical Owner may name one.
- **Option C (team choice inside a clinical band).** A mechanism already exists at organisation level: an override cannot lower the priority, cannot set the amount above twice the default, and cannot escalate later than the default (0035:524-535, 575-582; D-21). Those limits are engineering choices, not clinical ones. Option C keeps safety a precondition only if all of these hold:
  (1) the band limits are set by the Clinical Owner, not by engineering;
  (2) the server refuses values outside the band (as 0035 does);
  (3) a team can make a signal stricter, never switch it off or make it closable by hand (CR-041 untouched);
  (4) every change is audited with the actor, and only a registered nurse of the team or the Clinical Owner may change it (UNKNOWN who; `clinical`);
  (5) the value applied is the one of the team that owns the visit, also for a covered visit (CGR-21).
  Under these conditions I see no safety objection to C.
- **Delivery comes before thresholds.** A threshold only helps if the signal reaches a person (CGR-37, new). The package should treat recipients and delivery as part of the decision. Who must respond, and how fast, is clinical. How the signal is delivered is product.
- **CGR-35 and CGR-23.** CGR-35 is a documentation fact, not a threshold. The PO decided it (PLANNED); whether a move counts as making up missed care stays D-31/D-28 `clinical`. CGR-23 (the stuck clock restarts) is a threshold-semantics question the Clinical Owner must answer: does a pause stop the clock?
- **What the Clinical Owner must approve.**
  (1) Per signal: a value or a band (earliest P2, latest P1), and for untimed visits a time window.
  (2) The priorities.
  (3) Who must respond to each priority, and at which hours (with CGR-37).
  (4) Which signals may never be closed by hand (today CR-041, CR-049, CR-053).
  (5) Whether a pause restarts the stuck clock (CGR-23).
  (6) If C is chosen: who in a team may change the value.
  The PO may decide only how the signal is shown and delivered.
