# AIG1 — AI governance foundation

## Problem
The owner's direction (2026-10-27) makes planning, documentation, billing preparation and coordination increasingly AI-assisted, through the staged path approved the same day (D-35 stages 0-3). Today NAVORA has no place where a machine proposal is recorded, no way to tell a proposed value from a confirmed one, no correction measure and no stop. Every later assistant (PLAN3, A1 referral completeness, A4 invoice draft, A7 dictation) would have to invent these controls on its own, or run without them. The Strategic Alignment Review (dimension 2) rates AI-assisted operations *partial* with "no AI governance infrastructure"; the AI Operating Model Review §8 lists the controls; `cra` D-35 2(a)-(e) and `lca` D-35 terms set their protective shape. Stage 0 is "now, synthetic only": this item is stage 0.

## Users and journey step
Every confirmer of a proposal: the team (PLAN3 day plan), the primary nurse, the referrer, the licence holder. Operations and administrators see the agent health list. Journey: cross-cutting; first consumer Planning (PLAN3). `ARCHITECTURE.md`: minimisation → provider → schema → validation → human review → immutable approved state.

## Outcome
Any NAVORA assistant, rule-based or AI, can propose values; a named person confirms each value before it becomes record content; the record says who proposed and who confirmed; each agent's correction rate is visible per team and field, and the agent stops by itself when it crosses its written threshold. No AI service is called and no real data is used.

## Acceptance criteria
- [ ] **AIG1-1 Agent register.** A table of agents: key, name, level (`L`, `G`, `H`; D-34), kind (`rule` or `ai`), version, provider and region (null for `rule`), state (`off`, `on`, `stopped`), the written stop threshold (below) and who switched it on. Only an administrator of the organisation switches an agent on or off (audited). An agent of kind `ai` cannot be switched on in any environment while D-35 rule A holds: the switch refuses with a stated reason (pgTAP). An agent of level `G` or `H` cannot be switched on (D-34; the clinical module is a separate product, D-34 C).
- [ ] **AIG1-2 Suggestion ledger, append-only.** One row per proposal: agent key and version, the case or team it concerns, the input reference (identifiers of the rows read, never a copy of their content), the proposed values, the time. Update and delete are refused for every role, including the service role used by the app (pgTAP). Retention follows D-4 (no deletion before the final period).
- [ ] **AIG1-3 Provenance per value.** A proposed value becomes record content only through a confirm command by a named person, value by value or by an explicit list of values, each audited with confirmer and time. Each confirmed value carries its suggestion row; the record shows "vorgeschlagen von <Agent> / bestätigt von <Name> am <Datum>". A value the confirmer changes is stored as hers, with the proposal kept in the ledger as `corrected`. Signing a later document (F6) does not confirm a proposed value (pgTAP: a signed report with an unconfirmed proposal still shows it unconfirmed).
- [ ] **AIG1-4 "Not found" is explicit.** An agent that finds no value for a field returns `not_found` with the field name; the screen shows "nicht gefunden", never an empty value, "keine" or a default (unit and pgTAP: `not_found` can be confirmed only as "nicht gefunden", never turned into an empty value).
- [ ] **AIG1-5 No accept-all, scoped by field class** (amended by po 2026-10-27 15:20 before build start, AUT-1 #543; replaces the 13:35 wording "every field of every agent is confirmed one by one").
  - Every field an agent proposes carries a **class** in the register: `schedule` or `record` (everything else; the default). **`schedule` means only the responsible member of a visit inside the visit's own team, for its own date and time** (amended by po 2026-10-27 18:10, CGR-78 (a)). A field that sets a visit's date, time, team, minutes or category is `record`.
  - A **bulk confirm** (an explicit list of values the confirmer ticked, AIG1-3) is accepted only when every value in it is (i) a field of class `schedule`, (ii) proposed by an agent of kind `rule` and level `L`, and (iii) not on the organisation's one-by-one list. Every other value is confirmed one by one. There is no "alle übernehmen" without the ticked list.
  - Each value of a bulk confirm is still its own ledger confirmation with confirmer and time (AIG1-3), and the consuming command's own checks run again per value (for PLAN3: J3).
  - A field is classed `schedule` only by a migration that names its brief, and only after `cra` has confirmed the class in that brief. A field whose target is a safety alert (D-17), the care plan, a medical order or an assessment record (ASM1) can never be classed `schedule` (refused; the ADR names the target tables).
  - The organisation's one-by-one list is the Clinical Owner's (D-17 part 3, G-1). It can add any field, including a `schedule` field. Until it is set the list is empty and the class rule above is the whole default.
  - **Ticked list (CGR-78 (b), 18:10):** every line of a bulk-confirm list starts **unticked**; each line is ticked by its own tap; there is no "select all" control; the confirm button names its count. e2e at 390 px: the list renders with no line ticked, no single control ticks more than one line, and three ticked of five confirm exactly three.
  - pgTAP: (a) a bulk confirm containing a `record` field is refused; (b) a bulk confirm of `schedule` fields of a level-L `rule` agent is accepted and writes one confirmation row per value; (c) a bulk confirm of a field of a `G`, `H` or `ai` agent is refused; (d) a `schedule` field put on the organisation's list is refused in bulk; (e) classing a field `schedule` whose target is a care-plan, order, safety-alert or assessment table is refused, and classing a field that sets a visit's date, time, team, minutes or category `schedule` is refused (CGR-78 (a)).
- [ ] **AIG1-6 Scope inheritance.** An agent reads only through the confirmer's own access (RLS2, RLS3): proposals are computed in a call made as the confirming person, or by a job that reads only rows that person may read. pgTAP: a proposal for a case outside the caller's team is refused and writes no ledger row. No new read path; `READ_PATHS.md` updated.
- [ ] **AIG1-7 Correction rate per agent, field and team, never per person.** A read returns, per agent, field and team and per month: proposals, confirmed unchanged, corrected, rejected, `not_found`. No column, filter or export identifies the confirming person (pgTAP: the reader has no person column; a team with fewer than three confirmers in the month is suppressed, as AN1). Readable by the team for its own rows and by Operations for all teams of the organisation.
- [ ] **AIG1-8 Stop rule (P-6).** Each agent carries a written threshold: the correction share above which it stops, over a stated minimum number of proposals, and a window. An agent cannot be switched on without one (refused). When a closed window crosses the threshold, or when its version, provider or region changes without a new switch-on, the agent's state becomes `stopped`, it proposes nothing more, and one OPS1 exception "Assistent gestoppt: <Name>" reaches Operations (existing exception path; no new signal class). Restarting is a new audited switch-on. pgTAP: threshold crossed → `stopped` and no new ledger row; version changed → `stopped`.
- [ ] **AIG1-9 Evaluation harness on synthetic cases.** A test fixture of synthetic cases per agent with expected values; CI runs every switched-on-capable agent against it and fails when the share of matching values falls below the agent's stated evaluation bar. An agent without a fixture cannot be switched on. A synthetic test agent of kind `rule` (for example: propose the case's existing primary nurse for an unassigned visit) proves AIG1-1 to AIG1-9 end to end.
- [ ] **AIG1-10 Agent health list.** Operations and administrators see one list: agent, state, last proposal, last window's correction share, and why it stopped. e2e at 390 px for the confirm screen (one proposed value, "vorgeschlagen von", confirm, change, "nicht gefunden") and at desktop width for the health list.
- [ ] **AIG1-11 Confirmer read per value only (D-35 term 9; RLS3-4 pattern)** (added by po 2026-10-29 21:15 before build start, `aia` AUT-22 #686, `lca` 20:40 PR #689). (1) On the ledger and confirmation tables, the confirmer, the outcome (`confirmed`, `corrected`, `rejected`, and a confirmed `not_found`) and the confirmation time are **not selectable by `authenticated`** (and nothing by `anon`) through the table API; Engineering chooses the mechanism (for example column grants as in 0070) and names it in the ADR. (2) The confirmer is read only (a) per value, on the record line "vorgeschlagen von <Agent> / bestätigt von <Name> am <Datum>" (AIG1-3), through the record's own read function, for the people who may read that record, and (b) through the existing per-record AUD1 reader `read_audit_record(entity_type, entity_id, purpose)`, one entity per call. No function, view or export returns one confirmer together with the outcomes of more than one value, for any role, administrators included. (3) AIG1-7 stays the only aggregate and has no person key. (4) `READ_PATHS.md` lists the new columns under RLS3-4; the pgTAP 071 catalogue list includes the new readers and the AUD1 readers and fails on an unlisted function that returns a confirmer. **Tests (synthetic seed only):** pgTAP: a team member selecting each closed column directly gets 42501; `select *` and a count grouped by confirmer are refused; the record's read function still shows "bestätigt von" per value to the team; `read_audit_record` returns it with a stated purpose; pgTAP 071 fails on an unlisted reader.
- [ ] **AIG1-12 Look-back after a stop, per agent and window, never per person** (added by po 2026-10-29 22:10 before build start; `cra` CGR-95, advisory S2, PR #691; `lca` 21:45 D-35 terms (i)-(iv), PR #689 merged). When an agent becomes `stopped` (AIG1-8), the OPS1 exception "Assistent gestoppt: <Name>" links to one list of the **records** that hold a value from that agent confirmed unchanged (`confirmed`, not `corrected`) in the closed window that crossed the threshold, or, for a version, provider or region change, since the last audited switch-on. Terms: (i) the list and any export of it carry **no** confirmer, no outcome per person and no person filter; (ii) it holds only the records of that window or that period, nothing else; (iii) it is read only by the people who may already read each listed record, through the record's existing read path (AIG1-6), and by Operations for the OPS1 exception; no role gains a read; (iv) a line leaves the list once its value has been confirmed again or corrected through the normal confirm command (which writes its own ledger row); the list itself writes nothing into the record. Each line opens its record. **No rule is set** on whether, by whom or by when such values must be re-checked: that is the Clinical Owner's (D-17, G-1), UNKNOWN; the list only makes them findable. **Tests (synthetic seed only):** pgTAP: after a threshold stop the list holds exactly the records with an unchanged confirmation from that agent in the window (a corrected value and a value from another agent or outside the window are absent); after a version change it holds those since the switch-on; the list's result has no column naming a person or an outcome (catalogue check as in AIG1-11 (4)); a member of another team gets no line of a record she cannot read; a re-confirmation removes the line. e2e at desktop width: the OPS1 exception opens the list and a line opens its record.
- [ ] **AIG1-13 The look-back list is worked one by one, and a superseded value is labelled, not dropped** (added by po 2026-10-29 23:15 before the first AIG1 PR; `aia` AUT-23, medium, review 12, PR #695). (a) A value on an AIG1-12 list is re-confirmed or corrected **only one by one**: the AIG1-5 bulk confirm is refused for any value that is on a look-back list, whatever its class. (b) A listed value that is no longer the record's current value (a later confirmed value or a correction replaced it) is shown on the list as "überholt am <Datum>", under the same terms (i)-(iii) of AIG1-12, and is not counted as open in the OPS1 exception; it is **not removed**: whether a superseded value still needs a clinical re-check is the Clinical Owner's (D-17, G-1; UNKNOWN), and she may name such fields; NAVORA sets no rule either way. **Tests (synthetic seed only):** pgTAP: a bulk confirm that contains a listed `schedule` value is refused and writes nothing; the same value confirmed alone leaves the open part of the list; a superseded listed value reads `superseded` with its date, is absent from the open count and has no person column (catalogue check as AIG1-11 (4)). e2e at desktop width: a superseded line shows "überholt". Part of the first AIG1 PR if it is not yet opened; otherwise before AIG1 acceptance.
- [ ] **AIG1-14 The look-back screen names no person** (added by po 2026-10-30 00:15 before part (b); `uxa` UXR-49, medium, PR #685). The look-back list (AIG1-12, AIG1-13) is its own line layout, not the AIG1-3 value line: each line shows the record (case reference, visit date), the field and, where it applies, "überholt am <Datum>"; it shows **no** person name, no "bestätigt von", no outcome and no person filter or sort. A superseded line keeps the same single action (it opens its record) and shows no tick or "erledigt" mark. "bestätigt von <Name>" appears only after the line is opened, on the record's own AIG1-3 line, for those who may read that record. **Tests (synthetic seed only):** e2e at desktop width: the list opened from the OPS1 exception contains no confirmer's display name (the seeded confirmer's name is absent from the list region), no "bestätigt von" text and no control that filters or sorts by person; a superseded line shows "überholt am" and no tick. Part (b).
- [ ] **Negative.** No AI service is called in any test or environment; no client or staff data leaves the database; no person gets a read she did not have; no measure per person; nothing changes an existing record without a confirm command.

## Rules and their input class
- The stop threshold, the minimum number and the window are **per-agent configuration written by the person who switches the agent on**, not a NAVORA default. AIG1 ships no threshold value. For a `rule` agent of level L these are product settings; for anything touching clinical content they are not reachable (level G and H refused, AIG1-1).
- The list of one-by-one fields (AIG1-5) is a clinical safety list owned by the Clinical Owner (D-17 part 3). The field class (`schedule` or `record`) is a product classification by the PO with `cra`'s confirmation per field; it never reaches safety-alert, care-plan, order or assessment fields, which stay one by one whatever the list says.
- AIG1 adds no rule that ranks, routes or escalates a client. The only escalation is "agent stopped" to Operations, input class *visit/schedule fact* (a system state), not a client fact.

## Out of scope
- Any AI service, provider contract or model (D-35 stage 1 needs a new `owner` package: provider, region, contract, DPIA).
- Real data of any kind.
- The agents themselves beyond the synthetic test agent (PLAN3 is the first real consumer).
- Clinical drafting (A7-A10), interRAI content (D-36 A), per-person performance views (never, *Agents not to build*).

- Where does the evaluation harness live (pgTAP fixtures, vitest, or both)? It must run in CI on every PR that changes an agent.
- Is the AN1 small-team suppression reusable as is for AIG1-7?

- AIG1-7 suppression: reuse AN1's rule (a team with fewer than three confirmers in the month is suppressed). Whether three is enough to stop one person being inferred from a monthly share per agent and field (`lca` 20:40, UNKNOWN) is a design question: state in the ADR whether any AIG1-7 cell can be computed for a team with exactly three confirmers where one field had a single confirmer, and suppress that cell if so.
