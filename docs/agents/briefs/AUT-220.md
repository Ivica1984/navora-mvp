# AUT-220 — Budget tests under forced plans

Source: `aia` review 95 (`docs/agents/reports/AUTOMATION_REVIEW.md`); PO order «first after the acceptance» (journal `2026-11-26-0939-po.md`); design from `eng`, `docs/engineering/probes/AUT-220_ADR_DRAFT.md` (PROPOSED, merged #1785). Block HEIM-DP stays the frame. Technical guard like STAB1; not a feature, so it does not compete with HD-3s (README rule 12). One Engineering PR (`fix/` or `feat/`), tests only.

## Problem

ORDER-F1-F5 showed that a call-count defect can depend on the query plan and turn red in only one of ten `ci-repeat` runs. The budgets of pgTAP 178, 179, 180 run only under the default plan, so the same class of defect could return unseen.

## Users and journey step

None directly; protects `/order` and `/team` order lists (home, team, client) from timeouts on staging.

## Outcome

A plan-dependent per-row evaluation in the measured functions turns red on the first `db` run, under a named plan case.

## Acceptance criteria (contract = ADR draft, with these PO points)

- [ ] 178, 179, 180 run their existing call-count measurement under the four plan cases of 181; one assertion per case; **the same bound** in every case; no bound, timeout or assertion loosened.
- [ ] Wall-clock asserts only under `plan_default`; forced cases print the time with `diag()`.
- [ ] plpgsql trap handled: `discard plans` and `plan_cache_mode = force_custom_plan` per case, **and** a proof that the pin reached the body (settings read inside a plpgsql probe; `EXPLAIN` shapes captured; at least two different shapes asserted). If the cases do not yield different plans, the test is red and says so; no case is silently dropped.
- [ ] Proof that the guard bites: a probe commit on an unmerged branch running the frozen pre-F5 body goes red under at least one forced case; named in the ready report with the job link.
- [ ] `db` run-time increase measured and reported; tests only, no migration, no function change; `ci` green on the head.
- [ ] After merge: `ci` green on the merge commit. No `ci-repeat` acceptance needed beyond the next package acceptance (guard only), unless the `db` job turns intermittent.

## Rules and their input class

No product rule added or changed.

## AI leverage

No AI leverage: a deterministic test guard; reason: plan stability is a property to prove, not to predict.

## Gates

None (tests only, no visible behaviour). `aia` may comment; not a merge condition.

## Out of scope

Any change to the measured functions; new budgets; other test files.

## Merge order with HD-3s

One Engineering PR per run; the first `Paket prüfbereit:` merges first, on a tie AUT-220 (smaller, no gate); the other PR then merges `recovery/main` in.
