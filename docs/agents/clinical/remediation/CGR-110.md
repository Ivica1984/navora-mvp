# Remediation plan: CGR-110 (the SIG1 fallback-routing test, pgTAP 062 tests 47 and 50, fails depending on when it runs)

**Finding:** `cra` CGR-110, Clinical Governance Report 2026-11-03 05:30 (PR #807, read on its branch), **advisory (S3)**; blocking (S2) if a real routing difference is shown. Issue #399. PO *Active now* 2026-11-03 06:30, order (1). Engineering: ADR-137.

**Risk:** tests 47 and 50 are the only evidence that a P1 signal of an organisation with no team member and no Operations user reaches its administrator (H-01, H-02 routes). While they fail by chance, a real regression in that route would look like the known flake and be re-run to green.

**Cause (IDENTIFIED from the code; the new two-session check reproduces the mechanism in CI, CI decides; not run locally):** not a clock. `private.evaluate_signals` (0060:247) takes `pg_try_advisory_xact_lock('navora.sig1', org)` and returns 0 when another session holds it ("a concurrent one has the same result, so skip"). The local stack's pg_cron job `navora-sig1-signals` runs `evaluate_all_signals()` every minute and holds each organisation's lock until its whole run ends. It cannot see 062's uncommitted fixture. 062 evaluates org B exactly once; when that call met a scheduler run, it wrote nothing (test 47 have empty, test 50 have 0). Whether a run overlaps depends on where 062 falls within the minute, which looked like a time of day. The pinned clock is honoured on every path read (0067 rewrote every `now()`, guarded by pgTAP 068).

**No routing difference:** the recipients are computed by the same `signal_recipients` whichever session evaluates; a skipped evaluation is repeated by the next scheduler run (at most about a minute later, IMPLEMENTED since 0060). So the S2 escalation condition is not met (UNKNOWN only if CI shows otherwise).

**Affected code and data:** test only: `supabase/tests/database/062_sig1_safety_signal_delivery.test.sql`; new `scripts/db-concurrency/sig1-evaluation-lock.sh` and one line in the CI `Concurrency checks` step. No migration, no product function, no seed.

**Steps (IMPLEMENTED in the PR, CI decides):**
1. 062 takes both organisations' SIG1 evaluation locks at its start (waiting, never skipping) and asserts it holds them; every evaluation in the file then runs, the scheduler skips those two organisations until the rollback. No assertion changed, skipped or loosened (plan 54 → 55; old test 47 is now 48, old 50 is now 51).
2. Two-session check: (i) prints the scheduler job and its last run times; (ii) with another session holding org B's lock, `evaluate_signals(org B, true)` returns 0 and no delivery (the failure signature); (iii) after waiting for the lock, the delivery is `903=operations_fallback`.
3. Every further occurrence recorded on #399 until three later `db` runs with no 062 failure are named there (CGR-110 remedy 3).

**Needs a decision (not coded):** none for `clinical`. Note for `cra` and the PO (OPEN): a command that writes and evaluates in one transaction while a scheduler run is in progress also skips; its signal is delivered by the next run (≤ about one minute). That is the 0060 design, not changed here.
